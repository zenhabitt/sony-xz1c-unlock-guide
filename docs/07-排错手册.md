## 7.2 展开说明

### ① 「test2 not hit」是最常见的误判

不少教程说"XFL 版本太新"，**这是错的**。

xperable 需要的是 XFL 分区特定偏移处的 **O77 blob**，与分区其他内容、系统版本无关。

正确做法：把 `xfl-o77.mbn` 原样 `dd` 到分区开头，校验前 13,153,250 字节：

```sh
sha256sum /sdcard/xfl_head.bin
# 必须 = c745a32721d68bb7499a0e929bd9bcfec307cb922d0c17c22f064a51e6e1a7c7
```

对不上就是没写进去，或下载的 blob 损坏。

---

### ② 解锁后的开机循环

现象：Sony 防水动画 → 黑屏 → 重启 → 循环。

原因：原厂 `/data` 由 TEE 中的密钥加密。bootloader 解锁后 TEE 状态变化，
旧密钥解不开 → data 无法挂载 → 系统起不来。

按代价递增尝试：

```bash
fastboot -w            # 1. 先格式化
# 2. 不行就重刷原厂 8.0（newflasher）
# 3. 还不行就完整重刷 + 格式化
```

实机上是通过"重刷 docomo 8.0"恢复的。

---

### ③ newflasher 四个提示为什么全是 n

| 提示 | 不能答 y 的原因 |
|---|---|
| GordonGate 驱动 | 需要的话单独装 |
| dump trim area (TA) | **触发 buffer overflow 崩溃**，且没有 sake 认证也 dump 不出 DRM |
| 刷到 a/b 双槽 | 单卡机，双槽有风险 |
| flash persist | **丢失 attestation key，不可逆** |

---

### ④ Magisk 31 的 ADB su 限制

```
su: request rejected (2000)
```

Magisk 新版本移除了「超级用户访问权限」全局开关，ADB shell 发起的 su 默认 deny。

影响：`adb root`、脚本里用 su 会失败。不影响 App 内授权。

需要 ADB root → 装 Magisk 26.x / 27.x。

---

### ⑤ 时间不对导致的"玄学网络故障"

代理软件报「安全连接失败」、证书错误，排查到最后发现**系统时间差了两个多小时**。

```bash
$ADB shell date
```

修复：设置里手动改时间（自动同步依赖 NTP，UDP 123 常被屏蔽）。

## 7.3 诊断命令

```bash
# 设备状态
$ADB shell getprop ro.boot.verifiedbootstate   # orange = 已解锁
$ADB shell getprop ro.boot.flash.locked        # 0 = 未锁
$ADB shell getprop ro.build.version.release
$ADB shell getprop ro.build.id

# fastboot
$FB getvar unlocked
$FB getvar version-bootloader
$FB getvar all 2>&1 | grep -iE "unlock|lock|slot"

# 分区（需 root）
$ADB shell "ls -l /dev/block/bootdevice/by-name/"

# 日志
$ADB logcat -d | grep -iE "fatal|panic|avc"
$ADB shell dmesg | grep -i error
```

## 7.4 何时应当停手

- `newflasher` 报 `flash:bootloader FAILED`
- 设备管理器出现 `QUSB_BULK` / `9008`（EDL）
- 连续两次刷机失败且现象不同

EDL 恢复需要签名 firehose，普通手段很难救。正常操作**不会**进 EDL。
